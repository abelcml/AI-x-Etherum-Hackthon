# HSK 基础版：三块分工

## 共同目标
做一个演示：发布 GitHub 修复任务 → AI 开 PR → 指定测试通过 → 人工合并 → HSK 测试网付款。
基于 Handsel 修改，用测试币，不涉及真钱。只做一个仓库、一个小 bug。

## 你：做 HSK 基础版
1. 把网站和数据库跑起来。
2. 在 HSK 测试网部署测试币、Registry、Market，填好地址。
3. 接 GitHub App 和一个能修代码的 AI worker。
4. 跑一次完整付款；再跑一次取消或超时退出。
交付：能演示的页面、PR、交易链接。现有代码已包含链配置、部署脚本和付款校验，实际接入及部署待完成。

## 队友一：做可复现包
围绕同一份基础版整理，不另造大框架。
1. 写 README：安装什么、填哪些配置、按什么顺序启动。
2. 整理空白 env 模板，不放真实密钥。
3. 准备一个固定 bug 和对应测试，保证大家演示的是同一个案例。
4. 用新目录重新下载代码，照 README 跑一次，记录缺漏。
交付：README、配置模板、示例任务、复现记录。
完成标准：没参与开发的人也能照着跑。模型输出不必一模一样，验收结果要能检查。

## 队友二：做 PPT
做六页即可：
1. 项目：HSK 上的 AI 代码修复悬赏。用一句话写完整流程。
2. 问题：AI 可以写代码，但交付质量需要检查，付款需要明确依据。
3. 方案：任务 → AI → PR → 测试 → 合并 → 付款，画一张箭头图。
4. 技术：Handsel 提供基础；GitHub 管代码和验收；AI 做修复；HSK 管托管与结算。
5. 演示：放任务、修复 PR、测试结果、交易记录四张真实截图。没跑完的部分写“待验证”。
6. 我们做了什么：HSK 适配、同版本 CI＋合并付款校验、可复现说明。扩展到其他任务只作为未来方向。
交付：PPT 和三分钟讲稿。

## 配合方式
你做接入和部署；队友一边跟着操作边写说明；队友二先做前四页，等有真实结果再补演示页。
团队一起验收：成功付款一条、失败或退出一条。时间不够先减少功能，不重写页面、不做跨链或信用借贷。

# HSK 标签定价与任务结算框架
## 项目大纲与团队分工

## 1. 一句话介绍

在 HSK 上建立一套“标签定价＋任务验收＋自动结算”的框架，让不同类型的 AI 服务都能按照明确的任务范围交付并获得报酬。

**选择任务标签 → 确定价格和验收条件 → 托管赏金 → AI 执行 → 验收 → 付款。**

GitHub 代码修复是第一个演示案例。框架还希望适用于数据处理、翻译、内容制作等方向。

## 2. 我们说的“可复用框架”是什么

这里的目标是：同一套机制换个业务场景仍然能用，不只是让别人重新安装并运行同一份代码。

换应用时主要替换三样东西：

1. **标签与定价规则**：做什么、多大工作量、多少钱。
2. **执行器**：由哪个 AI 或工具完成任务。
3. **验收规则**：交付什么，怎样判断完成。

继续复用：任务状态、预算托管、交付记录、结算接口，以及失败、超时和争议处理。新场景是否真能复用，要通过第二个案例验证，不能仅凭设计图宣称完成。

## 3. 标签如何定价

标签要对应明确的工作范围，不能只有“简单／困难”。

一个任务可以包含：**任务类型＋输入规模＋交付格式＋质量要求＋期限**。

例子：

> 数据去重／CSV／最多 1 万行／保留指定字段／输出去重文件。
>
> 用户确认报价与验收条件 → 托管赏金 → AI 处理 → 检查字段、行数和重复项 → 通过后付款。

基础版先做少量预设任务套餐，由发布者确认最终价格；不要求实现复杂的动态定价算法。标签、价格和验收条件在接单前固定，修改时需要重新确认。

**标签决定服务范围和报价依据，不能代替实际验收。** 示例金额如需展示，应标为测试报价，不代表市场公允价格。

## 4. 可以应用在哪些方向

| 方向 | 标签示例 | 执行方式 | 验收方式 |
|---|---|---|---|
| 代码修复 | Python、小型 bug、补测试 | Coding worker 生成修复 PR | 指定测试通过＋人工合并 |
| 数据处理 | CSV、去重、字段提取、格式转换 | AI 或数据处理脚本 | 字段、格式、重复项等规则检查 |
| 翻译 | 中译英、技术文档、千字以内 | 翻译模型 | 格式检查＋人工审核 |
| 内容制作 | 商品描述、摘要、海报 | 文本或图像模型 | 内容要求检查＋人工确认 |

代码和数据任务可优先使用确定性测试；翻译、设计等主观任务保留人工确认，不声称 AI 能完全客观地判断质量。

## 5. HSK 在其中负责什么

- 托管任务赏金。
- 根据被授权的验收结果执行结算。
- 记录交易，方便核对资金流转。
- 按合约规则支持取消、超时退出或争议处理。

AI 执行和大部分验收发生在链下。链上负责资金与记录，不自动判断代码、翻译或图片是否优质。自动付款依赖平台提交合规的结算操作和正确的钱包权限。

对外技术名称采用 **“HSK 上的任务服务协议／应用协议层”**。它表达建在 HSK 上的业务框架，不宣称已经构建新的区块链 Layer 2 或 Rollup。

## 6. 四人分工

| 人员 | 负责内容 | 最终交付 |
|---|---|---|
| 你 | HSK 基础版 | 能演示的修复任务与链上付款 |
| 队友 A | 框架上半部分：标签定价与任务定义 | 标签表、定价规则、任务模板 |
| 队友 B | 框架下半部分：执行与验收适配 | 执行／验收接口、结果模板、第二场景流程 |
| 队友 C | PPT 与讲稿 | 六页 PPT、三分钟讲稿 |

### 你：做 HSK 基础版

- 复用 Handsel 页面和合约，跑起网站与数据库。
- 配置 HSK 测试网、测试币和普通钱包。
- 接 GitHub 与一个 coding worker。
- 跑通“任务 → PR → 同一版本测试通过 → 合并 → 付款”。
- 再验证一个取消或超时退出流程。

交付：能操作的基础版、修复 PR、测试记录和链上交易链接。

### 队友 A：标签、报价、任务怎么表达

负责“用户下单之前”的部分：

1. 选两个场景：代码修复、CSV 数据去重。
2. 给每个场景列标签，如任务类型、规模、输出格式、期限。
3. 写简单的固定套餐报价规则，展示金额标为测试报价。
4. 做统一任务模板，让两个场景都能填写。

交付：一张标签与报价表、一份任务字段表、两个填写好的任务例子。

不用做复杂定价算法，也不用等队友 B 的执行器完成。

### 队友 B：任务怎么执行、怎么证明完成

负责“接单之后”的部分：

1. 根据共同任务模板，说明如何选择并调用 AI 或脚本。
2. 定义提交结果的格式，记录产物及版本。
3. 分别写验收方式：代码修复用 CI＋合并；CSV 去重用字段与重复项检查。
4. 定义交给 HSK 基础版的结算请求：哪个任务、哪个产物版本、验收是否通过、证据在哪里。

交付：一张执行与验收流程图、一份结果／验收字段表、两个场景的处理示例。

不用重写链上合约。先用下面的共同任务样例工作，不用等队友 A 完成全部标签。只做方案时把输出标为“设计示例”，不能写成实际付款记录。

### 队友 C：做六页 PPT

1. 项目是什么：HSK 上的标签定价与任务结算框架。
2. 解决什么：范围和价格不清楚、AI 结果难验收、付款缺少统一依据。
3. 总流程：标签 → 报价 → 托管 → 执行 → 验收 → 付款。
4. 如何换业务：展示代码修复与 CSV 去重；哪些共用、哪些替换。
5. 基础版演示：真实任务、PR、测试、交易截图；未完成的写待验证。
6. 我们的贡献与后续：HSK 适配、付款校验、通用任务与适配接口。

先做前四页和第六页，等基础版有真实结果后补第五页。

## 7. 两个框架部分怎么同时做

先共用这一份最小接口约定，后面新增字段再相互确认：

| 任务输入（A 负责） | 结果输出（B 负责） |
|---|---|
| 任务编号、场景、标签 | 任务编号、运行编号 |
| 输入文件或任务说明 | 产物链接与版本／摘要 |
| 价格、代币和链 | 验收结果：通过／失败／待确认 |
| 交付要求、验收规则、期限 | 验收依据、证据链接 |

共同样例：

> 任务编号 demo-001；场景 CSV 去重；输入 sample.csv；最多 1 万行；按 id 去重并保留原字段；价格由 A 的测试套餐指定；输出 result.csv；验收检查 id 无重复、字段未丢失。

**A 用这个样例设计标签、报价和任务模板；B 同时用它设计执行、结果和验收模板。** 因此不需要串行等待。B 返回验收事实，由基础版按授权和合约规则决定能否结算，不能靠执行器自己声称成功就付款。

四人并行：你做真实 GitHub＋HSK 案例，A 和 B 做跨场景框架的两半，C 做介绍和展示。最后只需要对齐同一个任务编号、产物版本和验收规则。

本次先用测试网和测试代币。框架可以先交方案，不要求本轮全部实现；暂不做跨链、信用借贷、新链或完整商业市场。

当前基础代码已加入团队仓库的 handsel-hsk-implementation 分支并提交 PR #1。已有链配置、部署脚本和付款校验修改；真实 GitHub 联调、测试网部署与完整演示仍待完成。标签定价与通用场景接口属于设计目标，不代表当前代码已经全部具备。

## 8. 对外介绍短版

> 我们希望把 AI 服务变成范围明确、可验收、可结算的任务。用户通过标签选择服务，确认价格和验收条件后托管赏金；AI 完成任务，验收通过后在 HSK 上结算。GitHub 修复是首个演示，数据处理等场景可以通过替换执行器和验收规则接入。我们重点探索的是可跨场景复用的任务协议，而不是单一代码修复工具。

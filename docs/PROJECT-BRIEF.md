# AI 修复悬赏：项目与分工

## 我们做什么

做一个 AI 帮人修 GitHub bug、完成后领取赏金的演示。

**发任务 → AI 修代码并开 PR → 测试通过 → 人工合并 → HSK 测试网付款。**

基于 Handsel 修改，复用现有页面和合约；先跑一个仓库、一个 bug、一个 AI worker。使用测试代币，不涉及真钱。

## 怎么分工

每块指定一位负责人，谁有空可以兼任。名字由团队自己填。

| 工作 | 要做的小任务 | 完成标准 |
|---|---|---|
| ① AI 修复 | 准备一个简单 bug；接好模型和 worker；产出修复 PR | PR 里有真实修复，测试能通过 |
| ② 验收与后台 | 接 GitHub；核对指定测试和合并状态；触发结算 | 失败不付，只有同一版本通过并合并才付款 |
| ③ 链上付款 | 部署 HSK 测试合约；准备测试币；验证托管、付款和退出 | 能展示交易记录与余额变化 |
| ④ 整合与展示 | 配置并启动页面；写简短启动说明；串联演示和讲稿 | 从任务到到账能完整演一遍 |

①②③可以并行，④负责接起来。先成功跑通一次，再补失败／退款演示。

## 对外怎么讲

**我们尝试把 AI 做任务、独立验收和链上结算连接成一套可复用流程。代码修复是第一个案例，以后可替换成数据处理、内容交付等任务。**

“可复用框架”先作为方案方向，不要求本次实现所有场景。给负责方案的人三件小事：

1. 画一张“任务—执行—验收—付款”流程图。
2. 标出换业务时要换什么：任务输入、AI worker、验收规则。
3. 写一页复现说明：需要哪些配置、怎么启动、怎样证明跑通。

## 本次不做

不重写整个网站，不做跨链、信用借贷、多种业务市场或复杂治理。

## 最后交付

- 一份团队能运行的代码和配置说明。
- 一条成功修复并付款的演示记录。
- 一条失败或超时退出的记录。
- 一页项目介绍和流程图。
